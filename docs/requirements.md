# 个人记账应用需求文档

## 1. 项目概述

本项目是一个供个人长期使用的轻量级记账 Web 应用，同时作为公开在 GitHub 上的 Java 学习项目。应用部署在用户自己的电脑上；同一 Wi-Fi 网络中的电脑和手机可通过浏览器访问同一份账本数据。

第一版的目标是提供可靠、直观的日常收支记录、预算管理和统计能力，并通过前后端分离的实现过程学习主流 Java Web 开发方式。

## 2. 目标与范围

### 2.1 目标

- 让用户快速记录每笔收入或支出。
- 让用户按月掌握收支、预算使用和分类消费情况。
- 在电脑和手机浏览器中提供适配良好的使用体验。
- 以清晰的代码结构、文档和本地启动方式，作为可公开维护的开源项目。

### 2.2 第一版范围

- 单用户、单账本。
- 收入和支出记录。
- 收支分类管理。
- 月总预算和分类月度预算。
- 月度及分类统计与图表。
- 记录搜索、筛选、编辑和删除。
- 同一 Wi-Fi 网络内的跨设备访问。

### 2.3 不在第一版范围内

- 用户登录、权限控制和多人协作。
- 多账户管理，例如银行卡、现金、支付宝或微信余额。
- 云端部署、跨网络访问和自动同步。
- 导入、导出和自动备份。
- 多币种、汇率换算。

## 3. 用户与使用场景

### 3.1 目标用户

唯一目标用户是本项目作者本人。系统不需要注册或登录。

### 3.2 主要使用场景

1. 用户在手机上新增一笔午餐支出，填写金额、日期、分类和备注。
2. 用户在电脑上查看本月总收入、总支出、结余及分类消费图表。
3. 用户为当月设置总预算和餐饮、交通等分类预算，查看剩余金额或超支提示。
4. 用户查找某段日期、某个分类或某类收支的历史记录，并可编辑或删除错误记录。

## 4. 功能需求

### 4.1 收支记录

系统应支持新增、查看、编辑和删除收支记录。

每条记录包含：

- 类型：收入或支出。
- 金额：正数，精确到小数点后两位。
- 日期：默认为当天，可手动修改。
- 分类：从与记录类型匹配的已启用分类中选择。
- 备注：可选的简短文字说明。
- 创建时间和更新时间：由系统维护。

记录列表应按日期倒序显示；日期相同时，较晚创建的记录在前。

### 4.2 分类管理

系统应分别维护收入分类和支出分类。

- 初始提供常用默认分类。
  - 收入示例：工资、奖金、兼职、投资收益、其他收入。
  - 支出示例：餐饮、交通、住房、购物、娱乐、医疗、教育、其他支出。
- 用户可新增自定义分类。
- 用户可修改分类名称。
- 用户可停用分类；停用后不可用于新增记录，但历史记录及统计数据必须保留。
- 分类类型在创建后不可直接更改，以避免收入与支出统计混淆。

### 4.3 预算管理

预算以自然月为周期，且仅针对支出。

- 用户可为任意月份设置一个月总预算。
- 用户可为任意月份的一个或多个支出分类设置分类预算。
- 系统应显示预算金额、已支出金额、剩余金额和使用比例。
- 当已支出金额达到或超过预算时，系统应提供明确的视觉提示。
- 未设置预算的月份或分类不显示为超支。

### 4.4 搜索与筛选

用户可在记录列表中组合使用以下条件：

- 日期范围。
- 收支类型。
- 分类。
- 备注关键字。

筛选结果应同步显示匹配记录的收入合计、支出合计和结余。

### 4.5 统计与图表

系统应至少提供以下统计：

- 指定月份的总收入、总支出和结余。
- 指定月份的支出分类金额与占比。
- 指定月份的收入分类金额与占比。
- 指定月份的总预算与实际支出对比。
- 指定月份的分类预算与实际支出对比。

统计页面应允许切换查看月份。图表类型将在界面设计阶段确定，但应适合电脑和手机屏幕阅读。

## 5. 非功能需求

### 5.1 易用性

- 界面应同时适配桌面浏览器和手机浏览器。
- 新增一条常规收支记录应能在少量操作内完成。
- 金额、日期和必填分类缺失时应给出清晰的校验提示。

### 5.2 数据与可靠性

- 数据存储在运行服务的电脑本地 MySQL 实例中，由 phpStudy 提供和管理。
- 金额在后端必须使用精确的小数类型处理，避免浮点计算误差。
- 删除记录或分类前应要求用户确认。
- 数据库账户、密码和连接信息不得提交到 Git 仓库；仓库仅提供不含真实凭据的配置示例。
- MySQL 应仅接受本机上的 Spring Boot 连接，手机仅通过 HTTP 访问后端服务，不直接连接数据库。

### 5.3 可维护性与开源

- 采用前后端分离架构：React 前端、Spring Boot 后端、MySQL 数据库。
- 后端提供 REST 风格 JSON API。
- 前端与后端分别具备清晰的启动说明。
- 发布版本应支持由 Spring Boot 托管前端构建产物，使用户可通过启动一个 Java jar 使用应用。
- 项目 README 应说明功能、技术栈、本地运行步骤、phpStudy MySQL 配置、局域网访问方式及本地配置文件位置。

## 6. 初步技术约束

- 前端：React + TypeScript。
- 后端：Java 21 + Spring Boot + Maven，使用 IntelliJ IDEA 开发。
- 前端开发工具：VS Code。
- 数据库：phpStudy 管理的本机 MySQL。
- 网络：第一版仅支持本机和同一 Wi-Fi 局域网访问。
- 运行方式：电脑作为服务端；手机和电脑通过浏览器访问。

## 7. 验收标准

第一版完成时，应满足以下条件：

1. 用户能新增、修改、删除收入和支出记录。
2. 用户能管理收入与支出分类，并且停用分类不影响历史数据。
3. 用户能设置月总预算和分类月度预算，并看到超支状态。
4. 用户能按日期、类型、分类和备注筛选记录。
5. 用户能查看指定月份的收支汇总、分类统计和预算对比图表。
6. 在同一 Wi-Fi 网络中，手机浏览器能够访问电脑上运行的应用并读写同一份数据。
7. 项目能以公开仓库的形式提供完整的说明文档，且不包含真实账本数据。

## 8. 后续版本候选功能

- 数据导入、导出与手动备份。
- 云端部署与跨网络同步。
- 登录、多人账本和权限管理。
- 多账户与账户余额管理。
- 多币种支持。
- 交易附件、周期性记账和预算提醒。
